해당 문서는 기본적인 TypeScript에 관한 규정이다.
라이브러리 관련 내용은 `references/`에 있다.

# TypeScript 작업 규정

- 명확한 타입을 우선 사용하고 불필요한 `any` 타입 사용을 피한다.
    - 제네릭과 타입 추론을 적절히 활용하여 불필요한 형 변환을 피한다.
    - `any`가 불가피한 경우 사용 이유를 보고하고 범위를 최소화한다.
    - 타입 단언(`as`)과 non-null assertion(`!`)은 최소화하고,
      사용 시 안전성을 확인한다.
- 외부 API 응답은 타입 선언만으로 실제 데이터의 유효성이 보장된다고
  간주하지 않는다. 런타임 검증이 필요한 경우 프로젝트의 기존 검증 방식을 따른다.
- ky 라이브러리를 사용하여 외부 API와 통신한다.
- 공개 API, 재사용되는 유틸리티 및 코드만으로 의도가 명확하지 않은 부분에는 JSDoc을 작성한다.
- 코드의 동작을 그대로 반복하는 불필요한 주석은 작성하지 않는다.
- 기존 주석을 수정할 때는 실제 코드 동작과 일치하는지 확인한다.
- 새 코드에서 Deprecated로 표시된 API를 사용하지 않는다.
    - 기존 Deprecated API를 수정할 때는 대체 API와 호환성을 확인한다.
    - 대체 API가 없거나 마이그레이션 위험이 있으면 근거를 설명한다.
- 프로젝트에서 사용하는 ESNext의 안정화된 언어 기능을 적절히 활용한다.
    - 최신 문법을 사용하기 위해 불필요하게 코드를 복잡하게 만들지 않는다.
    - 기존 코드와의 일관성, 가독성 및 팀의 유지보수성을 우선한다.
- 예외 처리 시 구체적인 예외 타입을 우선 사용한다.
    - 처리하지 않은 기타 예외는 그대로 throw한다.
- 일반 함수 선언에는 `function` 문법을 사용한다.
- 콜백, 인라인 함수 및 화살표 함수가 적합한 경우에는 `() => {}` 문법을 사용한다.
- React 컴포넌트와 커스텀 Hook은 기존 프로젝트의 선언 스타일을 따른다.
